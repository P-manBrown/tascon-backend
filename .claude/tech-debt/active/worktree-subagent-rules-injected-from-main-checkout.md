# worktreeで動くサブエージェントに、worktreeではなくメインのcheckoutの`.claude/rules`が差し込まれる
- **Status:** Open
- **Priority:** Medium
- **Category:** Infrastructure
- **Area:** `.claude/rules/`、`.claude/skills/todoist-task-runner/SKILL.md`（`isolation: "worktree"`での委任）
- **Detected:** 2026-10-20
- **Todoist Task ID:** `6hpVmpCrfhc9rGfq`
- **Description:** Agentツールの`isolation: "worktree"`で起動したサブエージェントがファイルを読むと、`paths`で一致した`.claude/rules/*.md`が自動で差し込まれる。差し込まれるのはworktreeのファイルではなく、メインのcheckout（`/home/ruby/tascon-backend/.claude/rules/`）にあるディスク上のファイルである。2026-10-20に、mainから作られたworktree（`code-comments.md`が存在しない）で`app/controllers/application_controller.rb`を読ませたところ、メインのcheckoutの`code-comments.md`と`controllers.md`が差し込まれたことで確認した（Claude Code 2.1.304）。サブエージェントが自分でReadした場合は、worktreeのファイルが読まれる。
- **Impact:** worktreeとメインのcheckoutで`.claude/rules`の内容が食い違うと、サブエージェントは自分の作業するブランチと違うルールに従う。食い違いは、親セッションが別のブランチをcheckoutしている場合、メインのcheckoutにルールの未コミット変更がある場合、サブエージェントがworktreeでルールを書き換えた場合に起きる。明示的にReadしたworktree版と、差し込まれたメインのcheckout版の2つの内容が同時に文脈に入ることもある。ルールの変更前後の比較テストを`isolation: "worktree"`で行うと、変更前のはずのテストに変更後のルールが混ざる。普段のtodoist-task-runnerのように、親とサブエージェントが同じスタックの最上段にいてルールを書き換えない場合は、内容が一致するため表に出ない。
- **Proposed Resolution:** worktreeでルール・skillを書き換える作業や、ルールの版の違いに依存する作業では、親セッションのcheckoutをサブエージェントと同じブランチ・同じ内容にそろえてから委任する。それができない作業は`isolation: "worktree"`を使わずに行う。Claude Codeの今後のバージョンで差し込み元がworktreeに変わるかは、バージョン更新時に同じ手順で確かめる。
