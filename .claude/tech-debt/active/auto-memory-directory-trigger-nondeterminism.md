# claude-md-maintenance.mdのpathsトリガーが環境依存のautoMemoryDirectoryに依存し確定的でない
- **Status:** Open
- **Priority:** Low
- **Category:** Documentation
- **Area:** `.claude/rules/claude-md-maintenance.md`
- **Detected:** 2026-09-03
- **Todoist Task ID:** `6hQRP9CPwR6cgWqq`
- **Description:** `.claude/rules/claude-md-maintenance.md`のfrontmatter（`paths:`）に`.claude/memory/**/*.md`という固定パスがベタ書きされている。このpathsトリガーは、Claudeがmemoryファイルを読み書きする際に「Claude関連ドキュメント運用方針（プロジェクト全体のルールとして参照されるべき内容はmemoryではなくCLAUDE.md/rules/skillsへ書く）」を自動的に思い出させる目的で追加されたもの（`64d0b0d docs: close autonomy gaps in plan/docs/memory operation`）。
- **Impact:** 実際にmemoryが保存される場所は`autoMemoryDirectory`設定（`.claude/settings.local.json`、gitignore対象・ローカル限定）に依存する。現状はこの設定で`.claude/memory`（プロジェクト内、絶対パス）に固定しているため一致しているが、`autoMemoryDirectory`未設定の場合のデフォルトは`~/.claude/projects/<sanitized-cwd>/memory/`（プロジェクト外）であり、`.claude/memory/**/*.md`という固定パスとは一致しない。将来、別マシン・別環境でこのリポジトリを開いた際に`autoMemoryDirectory`の設定を引き継がないと、このpathsトリガーが発火しなくなる（memory書き込み時にClaude関連ドキュメント運用方針が読み込まれなくなる）。実害は「リマインダーが働かない」程度で致命的ではない。`autoMemoryDirectory`はセキュリティ上の理由でプロジェクト共有のsettings.jsonには書けない仕様（Claude Code公式スキーマで明記）のため、パス自体を共有ファイル側で確定させることはできない。
- **Proposed Resolution:** 個人開発の現状では対応不要（実害が小さく、確実性を上げるための実装コスト＝hookでautoMemoryDirectory設定を動的に読み取り判定する仕組み等＝に見合わない）。複数マシンで頻繁に開発するようになった場合、新環境セットアップ時に`autoMemoryDirectory`を`.claude/memory`へ設定する手順を明文化することを検討する。文言を注入して確認を促すだけのhookは採用しない（リマインダー型hookの廃止）。
- **Related:** [リマインダー型hookの廃止](../../../docs/decisions/reminder-hooks-removal.md)
