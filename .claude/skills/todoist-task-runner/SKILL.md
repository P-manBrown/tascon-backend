# todoist-task-runner

Todoistをタスクキューとして、execution-plan単位の実装〜ローカルコミットまでを連続処理する。対象タスクが尽きるまで自律的に繰り返す。リモートへの反映（PR作成・マージ）は行わない。

## 対象タスクの取得

- `Claude Code`ラベルが付いた未完了タスクを`find-tasks`で取得する（ラベルの意味・付与場所は`todoist-task-conventions` skill参照）
- 各タスクの`parentId`で分岐する
  - 親タスクがある場合: 親タスクに`tascon-backend`ラベルが付いているか確認する。付いていなければ対象外
  - 親タスクがない場合: そのタスク自体に`tascon-backend`ラベルが付いているか確認する。付いていなければ対象外
- Todoist上のトップレベルのタスクをセクション順・タスク順（並び順）に従って処理する

## 処理フロー

1. 取得したタスク（実処理単位）のdescription欄と、親タスク（親を持たない単発タスクはそのタスク自体）の既存コメント（`find-comments`）を確認する。既存コメントは、ユーザーによる追記指示や前回までの進捗（再開ケース）を把握するために確認する
2. `Agent`ツールで`isolation: "worktree"`を指定し新規サブエージェントへ委任する。手順1で取得した指示内容（description・既存コメント）を基に適切なpromptを作成して渡す
   - promptには積む先のブランチを明記する。未マージスタックの最上段を指定し、`main`は指定しない（`git-spice-workflow`のブランチ作成ルール参照）
3. サブエージェントは以下を参考に作業を自律的に行う（ユーザーの何らかのアクションが必要になった場合、「処理を停止する場合」の内容に従うこと）
   - planが作成されていない場合、`execution-plan` skillでplanを作成する
   - planが変更された場合や決定事項があった場合、planを編集する
   - **新規にexecution-planを作成した場合、実装着手前に`execution-plan`の計画作成手順(ユーザーへ提示・承認)に従い、「処理を停止する場合」の手順でユーザーの同意を得る。**判断に迷ったかどうかによらない強制トリガーであり、「自明に見える」という自己判断で省略しない。既存planの更新・再開時は対象外
   - `execution-plan`に従い連続実行する。Git操作は`git-spice-workflow` skillに従う
   - `codex-delegation` skillに従い実装をCodexへ委譲し（`Agent`経由で`codex:codex-rescue`を起動）、成果物を確認してからコミットする
   - 各Stepの完了時に、実施した作業内容の概要を`add-comments`で親タスクへコメントする。全Step完了後、最後のコメントを追加してから`complete-tasks`で「作業する」子タスクを完了させる（Stepごとには完了させない）
   - 処理を続行できない場合は「処理を停止する場合」の手順に従い、処理を一時停止する
4. サブエージェント完了後、親は結果を確認する
   - 通常完了の場合: 親セッション自身が`/code-review`と`/security-review`を実行し、そのexecution-plan分のdiffをレビューする
     - 指摘があれば、`CLAUDE.md`の実装委譲原則に従って修正し、レビュー対象と同じブランチへ新規コミットとして積む
     - 事実確認や実機検証が必要で機械的に直せない指摘（複数の記述の食い違いでどちらが正しいか不明な場合等）→ 自動修正せず「処理を停止する場合」の手順でユーザーの判断を仰ぐ
     - レビュー対応まで終わったら、サブエージェントのworktreeを「worktreeの片付け」に従って削除する。タスクの途中でセッションを中断・終了する場合は削除せず、worktreeをdetachし、そのタスクで作ったブランチをどのworktreeでもcheckoutされていない状態に戻す
     - 修正後の再度のレビューは行わない。指摘なしの場合はそのまま次のタスクを取得して「対象タスクの取得」、「処理フロー」に従って作業する（Todoistの対象タスクが尽きるまで繰り返す）
   - 処理停止の報告を受けた場合: 「処理を停止する場合」の手順で対応してから、そのサブエージェントを再開させる

## worktreeの片付け

- レビュー対応完了時のサブエージェントのworktreeと、随時発見した`.claude/worktrees/`配下の残存worktreeを対象にする
- 以下の条件をすべて満たす場合はユーザーに確認せず削除し、結果のみ報告する。満たさない条件がある場合は削除せず、その条件を報告する
  - 使用中のサブエージェントがなく、実行中でも再開予定でもない
  - `git -C <worktree> status --porcelain`の出力が空である。gitignore対象のログ・キャッシュ等は削除されるものとして扱う
  - HEADコミットが`main`または`worktree-agent-*`以外のローカルブランチに含まれることを、`git -C <worktree> branch --contains HEAD`で確認する
  - そのworktreeから起動したPuma等のプロセスが残っていない
- 条件を確認後、以下の順に実行する
  1. `git worktree remove <worktree>`を`--force`なしで実行する
  2. Agentツールが作成したブランチ`worktree-agent-<id>`を`git branch -d <branch>`で削除する。拒否された場合は、`git branch --contains <branch>`で先端コミットが`main`または`worktree-agent-*`以外のローカルブランチに含まれることを確認した場合のみ、`git branch -D <branch>`で削除する
  3. `git worktree list`と`git branch --list 'worktree-agent-*'`で結果を確認する

## 作業中に派生タスクを発見した場合

バグ、改善点、技術的負債等を発見した場合、処理は止めず`tech-debt-tracker` skillの手順に従う。ラベル付与を含むタスク作成手順は`tech-debt-tracker` skillに定義されている。

## 処理を停止する場合

`AskUserQuestion`は必ず親セッションが代行する。

以下のいずれかに該当したら、サブエージェントは処理を止め、ユーザーの対応を待つ。「判断に迷った」だけでなく、**ユーザーの何らかのアクションがなければ処理を続行できない状況全般**が対象。

- 判断に迷い、意思決定が必要な場合
- エラーが発生し、自力で解決できない場合（Codex実行の繰り返し失敗、テスト失敗が解消しない等）
- execution-planを新規作成した場合、実装着手前の確認（判断に迷ったかどうかによらない強制トリガー）

対応手順:

- サブエージェント側: 上記に該当したら、状況（何が起きていて、何が必要か）を明確にした上で、親へ報告し処理を一時停止する。execution-planの新規作成確認の場合はplanドラフトの内容を報告に含める
- 親セッション側: サブエージェントから報告を受けたら、内容に応じて対応する
  - 意思決定が必要な場合: 報告内容(execution-plan新規作成時はplanドラフトの内容)を基に`AskUserQuestion`等でユーザーへ提示し、同意を得る。修正を求められた場合はその指示をそのまま`SendMessage`でサブエージェントへ差し戻し、同意が得られるまで繰り返す
  - エラーの場合: エラー内容をユーザーへ伝え、対応方針を相談する
  - 対応後は`SendMessage`で元のサブエージェントへ結果を伝え、作業を再開させる。やり取りの内容がplanの`Decision Log`に記録すべき決定に該当するか必ず検討し、該当する場合はplanファイルへ追記するようサブエージェントへ併せて指示する
  

## 終了条件

- 担当タスク（「対象タスクの取得」の条件を満たすもの）が無くなったら終了

## 変更範囲

- 変更してよい対象: Todoistタスクの作成・完了処理、`.claude/plans/`、実装（サブエージェント経由でCodexへ委譲）、ローカルのコミット・ブランチ
- 変更してはいけない対象: リモートリポジトリへの操作（PR作成・マージ）。ユーザーの明示的な指示があるまで行わない
