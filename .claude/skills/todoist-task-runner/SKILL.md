# todoist-task-runner

Todoistをタスクキューとして、execution-plan単位の実装〜ローカルコミットまでを連続処理する。リモートへの反映（PR作成・マージ）は行わない。

## 対象タスクの取得

- `tascon-backend`ラベル（リポジトリ判別）と`Claude`ラベル（人間がAI処理を許可した明示的opt-in）の両方が付いたタスクを`find-tasks`で取得する
- `tascon-backend`だけでは「AIに処理してほしいタスクかどうか」を判定できないため、`Claude`ラベルで明示的に許可されたタスクのみを対象とする
- Todoist上のセクション順・タスク順（並び順）に従って処理する
- 「作業する」子タスクが未完了の親タスクのみを対象とする

## 処理フロー

1. 対象タスクをexecution-plan（機能）単位でグルーピングする
2. 各単位ごとに、`Agent`ツールで新規サブエージェントへ委任する。親セッションとは独立したまっさらなコンテキストで処理させることで、機能ごとにコンテキストが独立する（セッション切り替え相当）
3. サブエージェントは以下を行う:
   - まず親タスクのdescription欄を確認する。具体的な指示（対象・行動・終了条件等）が書かれていればそれに従う。空、またはタイトル程度の情報しかない場合は、タスクのタイトルと子タスクの内容から判断して作業する。指示は親タスクのdescriptionにまとめて書く（子タスク側には書かない。「AとBという別々の作業をどう分けるか」はタスク作成側の設計判断であり、`execution-plan`の規模基準や`git-spice-workflow`のブランチ粒度に従う）
   - `execution-plan` skillでplanを作成・更新する
   - `execution-plan`の自律実行モードに従い、1ステップずつブランチを切りgit-spiceでスタックしながら連続実行する
   - `codex-delegation` skillに従い実装をCodexへ委譲し（`Agent`経由で`codex:codex-rescue`を起動）、成果物を確認してからコミットする
   - 各Stepの「作業する」子タスクを`complete-tasks`で完了させる
   - 判断に迷った場合は「質問が必要な場合」の手順に従い、処理を一時停止する
4. サブエージェント完了後、親は結果を確認する
   - 通常完了の場合: 次の単位へ進む
   - 質問待ちの報告を受けた場合: 「質問が必要な場合」の手順で対応してから、そのサブエージェントを再開させる

## 質問が必要な場合

`AskUserQuestion`はサブエージェントには存在しない（親セッションのみが持つ）。実際に検証済み。そのため、質問の提示は必ず親セッションが代行する。

- サブエージェント側: 判断に迷ったら、まず`add-comments`で該当タスクにコメントを投稿する（人間への非同期通知）。質問内容を明確にした上で、親へ報告し処理を一時停止する
- 親セッション側: サブエージェントから質問の報告を受けたら、`AskUserQuestion`で選択肢を提示してユーザーの応答を得る。応答を得たら`SendMessage`で元のサブエージェントへ回答を伝え、作業を再開させる

## 終了条件

- 担当タスク（`tascon-backend`ラベル・`Claude`ラベル、「作業する」子タスクが未完了）が無くなったら、何もせずセッションを終了する

## 変更範囲

- 変更してよい対象: Todoistタスクの作成・削除・完了処理、`.claude/plans/`、実装コード（サブエージェント経由でCodexへ委譲）、ローカルのコミット・ブランチ
- 変更してはいけない対象: リモートリポジトリへの操作（PR作成・マージ）。人間の明示的な指示があるまで行わない

## 他skillとの責務分離

- `execution-plan`: 個々のplan文書管理を担当。このskillから呼ばれる
- `git-spice-workflow`: コミット・ブランチ・PR操作を担当
- `codex-delegation`: Codexへの実装委譲手順を担当
- `todoist-task-runner`: 上記を束ね、Todoistとの同期・タスクキューの消化を担当

## 検証済み事項

- `AskUserQuestion`はサブエージェントのツール一覧・`ToolSearch`いずれにも存在しない。親セッションのみが持つ
- サブエージェントから`Agent`ツール経由でさらに別のサブエージェント（ネストしたサブエージェント）を起動できる。`general-purpose`同士での起動・完了を実機確認済み
- サブエージェントからBashツールは問題なく使える
- サブエージェントから`Agent(subagent_type: "codex:codex-rescue")`でCodexへの実装委譲が機能する。ファイル作成・中身とも期待通り、他ファイルへの副作用なしを実機確認済み
- 質問フロー全体（サブエージェントがTodoistへコメント投稿→親へ報告し一時停止→親が`AskUserQuestion`でユーザーに確認→`SendMessage`で元のサブエージェントへ回答を伝え再開→再開後の処理継続）が意図通り動作することを実機確認済み
- `execution-plan`自律実行モード（複数Stepをそれぞれ別ブランチとしてgit-spiceでスタックし、Step間で人間の確認を待たずに連続実行する）が実機確認済み。テストタスクで2Stepを連続実行し、各Stepが1コミットで完結、意図通りスタックされることを確認した
- `todoist-task-runner`の「作業する」子タスクの`complete-tasks`による完了処理も実機確認済み
- 「既存の仮タスクを削除してから確定Step構成でタスクを作り直す」フローも実機確認済み。仮タスク2件削除→新Step3件＋孫タスク12件の再生成、ラベル継承まで確認した
- `gs branch create <name> -m "..."`（ブランチ作成とコミットメッセージ指定を同時に行う形）はmainブランチ上のprotect-branchフックに阻まれてエラーになることを確認した。回避策として`--no-commit`で先にブランチを作成・checkoutしてから`git commit`を別途実行する2段階の手順を使うこと

## 未検証事項

- 実際のTodoist機能開発タスク（テスト用の仮想タスクではなく）での一気通貫実行はまだ実績がない。個々の部品は全て検証済み
- PR作成・マージのトリガー対応は、`todoist-task-runner`固有の仕組みではなく既存の`git-spice-workflow` skillの通常動作そのものであり、独立した検証は不要と判断した
